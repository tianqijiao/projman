# 运维项目管理工具需求文档

版本：v0.2 审核同步稿  
日期：2026-05-23  
适用工程：`D:\CodexLab\projman`

## 1. 背景与目标

用户负责高职院校信息中心相关运维项目管理。典型项目包括行政电脑维护服务、机房维保、安全服务、云平台服务等。项目从年度预算、采购依据准备、合同审签、合同签订、验收、付款到下一期续采，过程中会产生多类 PDF 材料。

本工具目标是提供一个本地运行、轻量可靠的运维项目台账系统，用于：

- 记录每个运维项目的年度、预算、合同、验收、付款和备注信息。
- 归档项目全过程 PDF 证据材料。
- 管理跨年度合同和分年度执行、验收、付款情况。
- 快速查看某一年还有哪些项目未签合同、未验收、未付款、资料不完整。
- 在合同即将到期时提醒启动下一期采购。
- 按当前筛选条件导出台账 Excel，便于汇报和留存。

## 2. 使用场景

### 2.1 年度预算项目建档

每年预算下一年度运维项目，经审批后形成预算金额。用户需要先录入项目名称、年度、预算金额和备注，使项目进入年度台账。

### 2.2 采购和合同材料归档

项目采购、合同审签和合同盖章过程中产生以下项目级 PDF 材料：

- 采购依据，例如会议纪要、经费审批单。
- 合同审签 PDF。
- 盖章合同扫描件。
- 其他附件。

这些材料需要与项目主档绑定，支持上传、预览、下载和删除。

### 2.3 验收与付款管理

项目执行完成后，需要记录验收日期、付款日期，并归档：

- 验收单 PDF。
- 发票 PDF。

对于一年期项目，验收付款可能发生在合同当年，也可能发生在下一年。对于多年期项目，可能按年验收、按年付款。

### 2.4 跨年度执行

有些项目建档/签约年度和实际服务年度不一致。例如 2026 年完成采购和签约，服务期为 2027 至 2029 年。系统需要将项目展开为多个年度执行记录：

- 建档年度早于服务期首年时，建档年度可作为“合同管理年”。
- 服务期内每一年作为可执行年度，默认均分预算金额和合同金额。
- 用户可以手动调整某一年度预算、合同金额，或将某一年标记为“合同管理年”。
- 缩短合同期时，超出新合同期的年度执行记录和对应年度附件应同步清理。

### 2.5 年度看板与台账筛选

用户需要按年度查看：

- 项目总数。
- 已立项数量。
- 未签合同数量。
- 未验收数量。
- 未付款数量。
- 到期续采提醒。

项目台账需要支持按年度、关键词和状态筛选，并展示当前筛选范围内的预算合计、合同合计和待补资料数量。

### 2.6 数据迁移与本地运行

工具面向个人或小范围内网使用，默认本机运行，也可通过局域网或 Tailscale 访问。迁移到另一台电脑时，应保留 `data/` 目录和 `.env` 配置，避免覆盖真实业务数据。

## 3. 用户与权限

当前 MVP 只定义一个系统使用者：

- 管理员/项目管理者：登录系统，维护项目台账，上传和下载附件，删除误录项目或附件，调整系统设置。

当前系统采用简单账号密码登录，账号、密码和密钥通过环境变量或 `.env` 配置。默认账号密码为 `admin/admin`，正式使用前应修改。

暂不包含多人角色、部门权限、细粒度审计、统一身份认证等能力。

## 4. 功能需求

### 4.1 登录与会话

- 用户访问业务页面前必须登录。
- 登录成功后进入年度看板或项目台账。
- 用户可以退出登录。
- 未登录访问业务页面时跳转到登录页。

### 4.2 年度看板

- 默认展示当前自然年度。
- 支持切换年度。
- 展示年度项目总数、已立项、未签合同、未验收、未付款。
- 展示合同即将到期的项目，并提示启动下一期采购。
- 续采提醒提前天数默认为 60 天，可在设置中调整。

### 4.3 项目台账

- 支持查看全部年度或指定年度的年度执行项目。
- 支持关键词搜索，当前搜索范围包括项目名称、项目备注和年度备注。
- 支持状态筛选：
  - 全部状态。
  - 未签合同。
  - 未验收。
  - 未付款。
  - 资料不完整。
  - 已完成。
- 台账列表展示年度、项目名称、预算金额、合同金额、合同期、状态、附件摘要、下载入口和删除操作。
- 合同管理年应有明确标识，并不计入验收、付款待办。
- 台账筛选条件应在进入详情、预览附件、返回台账和删除后尽量保留。
- 年度筛选、关键词筛选、状态筛选和 Excel 导出应使用同一套筛选结果，避免页面看到的项目与导出的项目不一致。

### 4.4 项目新增

- 新增项目至少需要填写年度和项目名称。
- 年度必须是有效整数。
- 项目名称不能是空白字符串；手工提交空白名称时应拒绝保存并提示错误。
- 可填写预算金额和备注；预算金额必须是有限数字。
- 新增项目默认进入对应年度台账。
- 新增项目页默认年度为当前年份加一，符合下一年度预算建档习惯。

### 4.5 项目主档维护

项目详情页支持维护：

- 建档/签约年度。
- 项目名称。
- 项目预算总额。
- 合同总额。
- 合同开始日期。
- 合同结束日期。
- 项目备注。

主档保存后，需要同步生成或刷新年度执行计划。
项目名称不能为空；金额字段必须是有限数字；合同开始日期不能晚于合同结束日期。上述校验失败时，应返回可控中文错误，不应抛出 500。

### 4.6 年度执行维护

每个项目按年度展示年度执行记录。年度执行记录支持维护：

- 年度预算。
- 年度合同金额。
- 验收日期。
- 付款日期。
- 是否为合同管理年。
- 年度备注。

系统默认根据合同服务期展开年度执行记录，并在多个付款年度之间均分预算和合同金额。用户手动调整年度金额或合同管理年后，系统应保留该手动设置。
年度金额必须是有限数字；验收日期和付款日期必须是有效日期。校验失败时，应返回可控中文错误，不应抛出 500。

### 4.7 附件管理

系统只支持上传 PDF 附件。上传时同时检查文件扩展名和文件头。

项目级附件类型：

- 采购依据。
- 合同审签 PDF。
- 盖章合同扫描件。
- 其他附件。

年度级附件类型：

- 验收单。
- 发票。

新增上传入口应按项目级/年度级类型限制。旧数据中如果已经存在项目级验收单、发票，应继续兼容展示，并可参与首个年度执行记录的状态计算。

附件能力包括：

- 上传。
- 列表展示。
- 浏览器内预览。
- 单个下载。
- 删除附件，同时清理磁盘文件。
- 下载项目全部附件 ZIP。
- 下载某一年度执行相关附件 ZIP。

### 4.8 状态计算

项目状态由字段和附件共同决定：

- 已立项：存在预算金额，或年度执行有预算金额，或该年度为合同管理年。
- 合同已签：存在合同金额、合同开始日期、合同结束日期，并且已上传盖章合同扫描件。
- 已验收：存在验收日期，并且已上传验收单。
- 已付款：存在付款日期，并且已上传发票。
- 资料不完整：缺少盖章合同扫描件、验收日期、验收单、付款日期或发票等关键证据。

合同审签 PDF 不能替代盖章合同扫描件，不能单独使项目进入“合同已签”状态。

合同管理年只要求合同状态，不要求验收和付款材料，也不因为缺验收单或发票而计入验收、付款待办。

### 4.9 预算与合同金额

- 项目主档记录预算总额和合同总额。
- 年度执行记录记录分年度预算和合同金额。
- 默认分年度金额按可付款年度均分。
- 用户可手动覆盖年度金额。
- 系统计算预算差额：预算金额减合同金额。
- 合同金额超过预算金额时，预算差额为负数，应以风险样式提示，但当前 MVP 不阻止保存。

### 4.10 Excel 导出

- 项目台账可按当前筛选条件导出 Excel。
- 导出内容包括年度、项目名称、预算金额、合同金额、预算差额、合同开始、合同结束、验收日期、付款日期、状态、缺少材料和备注。
- 导出不包含附件文件名和附件明细。
- 金额列应保留数值格式，便于后续统计。

### 4.11 设置

- 支持设置续采提醒提前天数。
- 设置保存到本地数据库。
- 默认值为 60 天。
- 当前仅接受正整数输入；非数字由 FastAPI 表单校验兜底，0 或负数会返回业务错误提示。

### 4.12 表单输入校验与错误反馈

所有来自表单或手工请求的输入都应在服务端校验，前端 `required`、`type="number"` 和 `type="date"` 只作为用户体验辅助，不作为唯一防线。

- 项目名称：去除首尾空格后不能为空。
- 年度：必须是有效整数；非法台账筛选年度回退为全部年度。
- 金额：必须为空值或有限数字，拒绝 `abc`、`inf`、`-inf`、`nan`、`1e309` 等不可解释值。
- 日期：必须为空值或 `YYYY-MM-DD` 格式的有效日期。
- 合同期：开始日期不能晚于结束日期。
- 续采提醒天数：必须为正整数。
- 上传附件：类型必须属于当前入口允许的附件类型，且文件扩展名和文件头都必须符合 PDF。

校验失败时应返回 400 或页面可识别的中文错误，不应出现 500。

### 4.13 删除

- 支持删除项目。
- 删除项目时同步删除：
  - 项目主档。
  - 年度执行记录。
  - 数据库附件记录。
  - 磁盘上的附件 PDF 文件。
- 支持删除项目级附件和年度级附件。
- 删除前应有浏览器确认提示。

运行时数据位于 `data/`：

- `data/app.db`：SQLite 数据库。
- `data/attachments/`：项目级附件。
- `data/annual_attachments/`：年度级附件。

真实业务数据不进入 Git。

### 5.2 主要数据对象

项目主档：

- 建档/签约年度。
- 项目名称。
- 项目预算总额。
- 合同总额。
- 合同开始日期。
- 合同结束日期。
- 验收日期。
- 付款日期。
- 备注。
- 创建时间。
- 更新时间。

年度执行：

- ID。
- 项目 ID。
- 年度。
- 年度预算金额。
- 年度合同金额。
- 是否合同管理年。
- 验收日期。
- 付款日期。
- 年度备注。
- 是否手动金额。
- 创建时间。
- 更新时间。

附件：

- ID。
- 关联项目或年度执行记录。
- 附件类型。
- 原始文件名。
- 磁盘存储路径。
- 上传时间。

系统设置：

- 设置键。
- 设置值。

## 6. 非功能需求

### 6.1 运行环境

- Windows PowerShell 为主要使用环境。
- Python 版本要求为 3.13 及以上。
- 依赖管理使用 `uv`。
- 启动脚本应自动创建 `.venv`，并读取 `.env` 配置。
- 服务默认监听 `0.0.0.0:8765`，便于局域网或 Tailscale 访问。

### 6.2 易用性

- 页面应以台账和看板为主，避免复杂配置。
- 表格适合横向信息扫描。
- 项目详情页保存表单后应尽量保持滚动位置，避免用户从页面顶部重新找位置。
- 附件类型和状态标签使用中文业务名称。

### 6.3 数据安全

- 默认不提交 `data/`、`.env`、`.venv`。
- 删除附件和项目时需要确认。
- 附件读取应限制在配置的数据目录下，避免任意路径删除风险。
- 附件预览、下载、打包和删除都必须通过数据目录边界校验，不能读取或删除 `data/` 之外的文件。
- 正式使用前必须修改默认密码和密钥。

### 6.4 可维护性

- 领域逻辑、服务逻辑、Web 路由、导出逻辑和模板分层。
- 核心状态计算和年度执行展开逻辑需要有自动化测试覆盖。
- 更新另一台电脑上的现有项目时，应只覆盖代码，不覆盖 `data/` 和 `.env`。

- 在线审批流、流程流转、电子签章。

- 除 PDF 以外的正式附件格式。

## 9. 验收标准

### 9.1 基础流程验收

用户能够完成以下闭环：

1. 登录系统。
2. 新增一个下一年度预算项目。
3. 录入合同金额和合同起止日期。
4. 上传采购依据、合同审签 PDF 和盖章合同扫描件。
5. 在年度执行中录入验收日期、付款日期。
6. 上传验收单和发票。
7. 在台账中看到项目状态从未签合同、未验收、未付款逐步变为已完成。
8. 导出当前筛选台账 Excel。
9. 下载项目全部附件 ZIP。

### 9.2 跨年度项目验收

对于服务期跨多个年度的项目：

- 系统能按合同开始和结束年份生成年度执行记录。
- 合同开始日期晚于合同结束日期时禁止保存，并返回中文提示。
- 建档年度早于服务期首年时，建档年度可以作为合同管理年。
- 每个服务年度可分别维护验收、付款和附件。
- 手动调整的年度金额不会被后续主档保存覆盖。
- 缩短合同期后，超出新合同期的年度记录和附件被清理。

### 9.3 删除与数据清理验收

- 删除项目时，数据库记录和磁盘附件文件同步清理。
- 删除单个附件时，附件记录和磁盘文件同步清理。
- 删除后返回台账时保留原筛选上下文。

### 9.4 运行与迁移验收

- 在项目根目录执行 `.\scripts\start.ps1` 能启动服务。
- 本机可访问 `http://127.0.0.1:8765`。
- 迁移到另一台电脑时，复制代码、`.env` 和 `data/` 后能继续使用原数据。

## 10. 待确认问题

以下问题不是当前 MVP 的阻塞点，但会影响下一阶段需求边界：

1. 是否继续保持单用户本地工具定位，还是需要多人登录和角色权限？
2. 是否需要导入历史 Excel 台账，批量生成项目和年度执行记录？
3. PDF 附件是否长期限定为 PDF，还是要支持 Word、图片、压缩包等补充材料？
4. 多年合同金额默认均分是否符合实际，还是需要支持按合同条款配置每年付款比例？
5. 续采提醒是否需要“已启动下一期采购”状态，避免到期项目持续提醒？
6. 是否需要项目状态变更日志或操作审计，用于事后追踪谁在什么时间改了什么？
7. 是否需要自动备份 `data/`，以及一键恢复机制？
8. 是否需要按项目类型、采购方式、供应商、经费来源、合同编号等字段扩展台账？
9. 是否需要对即将到期、超预算、资料不完整项目做更明显的提醒或汇总导出？
10. 是否需要把当前工具部署为 Windows 后台服务或开机自启动？

## 11. 后续建议

下一阶段如果继续开发，建议优先级为：

1. 增加历史台账导入和字段扩展，降低已有项目补录成本。
2. 增加备份/恢复说明或工具，保护 `data/` 中的真实业务资料。
3. 增加“续采已处理”或“下一期项目关联”能力，让续采提醒从提示变成闭环。
4. 增加供应商、合同编号、经费来源等常用管理字段。
5. 视使用范围决定是否扩展多人账号和审计日志。
