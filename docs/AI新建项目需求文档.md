# AI 辅助新建运维项目需求文档

版本：v0.1 草案  
日期：2026-05-25  
适用工程：`D:\CodexLab\projman`

## 1. 背景与目标

当前运维项目管理工具已经支持手工新增项目、维护合同信息、维护年度执行记录、上传 PDF 附件和导出台账。实际使用中，很多项目的关键信息已经存在于合同、采购依据、审签材料、截图或用户临时文字说明中。逐字段手工录入容易慢、漏填，也容易把合同金额、日期等信息抄错。

本功能新增一个“AI 辅助建档”模块，用于从用户上传的合同/PDF/图片或手写文字中提取运维项目信息，生成一个可编辑的项目草稿。用户必须先查看、修改并确认后，系统才创建正式运维项目。

核心目标：

- 降低新建项目时的手工录入成本。
- 从合同、截图、说明文字中自动识别项目名称、年度、金额、合同期等字段。
- 提供清晰的 AI 识别依据，让用户知道每个字段从哪里来。
- 坚持人工审核边界，AI 只能生成草稿，不能直接写入正式台账。
- 保留原始输入材料，便于后续追溯。

## 2. 使用场景

### 2.1 上传合同生成项目草稿

用户上传一份合同 PDF 或合同扫描件，系统调用外部 AI/API 识别合同内容，并生成项目草稿。草稿应尽量包含：

- 项目名称。
- 建档/签约年度。
- 合同总额。
- 合同开始日期。
- 合同结束日期。
- 可能的预算金额。
- 可作为备注的信息，例如供应商、合同编号、服务内容摘要、付款方式等。

用户查看识别结果后，可以修改字段，再确认创建项目。

### 2.2 上传图片生成项目草稿

用户上传合同截图、采购材料截图、经费审批截图或其他图片，系统调用支持图像理解的 AI/API 提取信息。图片可以作为临时 AI 输入材料，但当前正式附件仍以 PDF 为主。

如果用户最终确认创建项目，系统应询问或默认将原始图片记录为“AI 输入来源”，不直接作为正式项目附件；若后续需要归档为正式材料，应由用户另行上传 PDF。

### 2.3 输入文字生成项目草稿

用户在文本框中粘贴或输入一段说明，例如：

```text
2027 年行政电脑维护服务，预算 5 万，合同金额 4.8 万，服务期 2027-01-01 到 2027-12-31。
```

系统调用 AI/API 或本地解析逻辑，将文字转换为项目草稿。用户复核后确认创建项目。

### 2.4 多材料综合识别

用户可以同时提供文字说明和一个文件。系统应综合材料生成草稿，但必须在结果中标明字段来源。例如：

- 合同金额来自合同第 2 页。
- 项目年度来自用户文字说明。
- 合同结束日期来自合同截图。

## 3. 用户与权限

当前 MVP 仍保持单用户本地工具定位。只有已登录用户可以使用 AI 辅助建档。

未登录访问 AI 模块时，应跳转登录页。

## 4. 功能范围

### 4.1 AI 建档入口

系统新增一个独立入口，例如：

- 顶部导航：`AI 建档`。
- 或项目台账页面按钮：`AI 新建项目`。

进入页面后，用户可以选择以下输入方式：

- 上传 PDF。
- 上传图片。
- 输入文字。
- 同时上传文件并输入文字。

至少需要提供一种输入。

### 4.2 支持的输入类型

MVP 支持：

- PDF：合同、审签材料、采购依据等。
- 图片：PNG、JPG、JPEG、WebP。
- 纯文本：用户手写说明或复制的合同片段。

MVP 不要求支持：

- Word、Excel、压缩包。
- 批量多文件识别。
- 一次识别多个项目。

如果上传不支持的文件类型，系统应返回中文提示，不调用 AI/API。

单次上传文件默认上限为 10 MB，可通过 `PROJMAN_AI_MAX_UPLOAD_MB` 调整。超过大小限制时，系统应返回中文提示，不保存 AI 输入文件，不调用 AI/API。

### 4.2.1 PDF 处理策略

MVP 明确采用“优先提取 PDF 文本，失败后自动转图片页识别”的路线：

- 系统先保存上传 PDF 为 AI 输入文件，再尝试本地提取 PDF 文本。
- 提取成功后，只把规范化后的文本、原始文件名和必要的页码/来源信息传给 AI 客户端。
- PDF 文本为空时，系统自动将 PDF 前若干页渲染为 PNG 页面图片，并把页面图片交给支持视觉理解的 AI 客户端识别。
- PDF 加密、PDF 损坏、文本提取失败且页面图片也无法生成时，系统返回中文提示，不调用 AI/API，不创建草稿。
- 扫描件 PDF、图片型 PDF 可以直接上传；用户不需要手工截图。图片过暗、倾斜严重、页数过多或多合同合并 PDF 可能影响识别质量，仍需用户在文字说明中补充关键信息。
- 后续如果改为直接向模型发送 PDF 原文件，必须先更新本需求、测试计划和 fake client 输入契约。

### 4.3 AI 识别字段

AI 应输出结构化草稿，字段分为“可直接入库字段”和“仅供参考字段”。

可直接入库字段对应当前项目主档：

- `year`：建档/签约年度。
- `name`：项目名称。
- `budget_amount`：项目预算总额。
- `contract_amount`：合同总额。
- `contract_start`：合同开始日期。
- `contract_end`：合同结束日期。
- `notes`：项目备注。

仅供参考字段不直接写入当前数据库，默认追加到备注或在草稿页展示：

- 供应商名称。
- 合同编号。
- 服务内容摘要。
- 付款方式。
- 采购方式。
- 经费来源。
- AI 识别的风险提示。

### 4.4 字段来源与置信度

AI 识别结果页必须展示每个字段的来源和可信程度，避免用户盲信。

每个字段建议展示：

- 字段名。
- AI 建议值。
- 来源材料，例如“上传 PDF”“上传图片”“用户文字”。
- 来源摘录或证据片段。
- 置信度：高 / 中 / 低。
- 是否需要人工重点确认。

低置信度字段应有明显提示。

### 4.5 草稿复核与确认

AI 识别完成后，系统进入“项目草稿确认页”。

草稿页必须允许用户编辑：

- 年度。
- 项目名称。
- 预算金额。
- 合同金额。
- 合同开始日期。
- 合同结束日期。
- 备注。

用户操作：

- `重新识别`：返回输入页或重新调用 AI/API。
- `放弃草稿`：丢弃本次识别结果，不创建项目。
- `确认创建项目`：按用户最终修改后的字段创建正式项目。

AI 识别结果不得绕过用户确认直接入库。

草稿生命周期：

- 草稿默认保留 24 小时，可通过 `PROJMAN_AI_DRAFT_TTL_HOURS` 调整。
- 待确认草稿可以被用户放弃；放弃后状态变为“已放弃”，不能再次确认。
- 已创建草稿不能重复确认，避免重复创建项目。
- 放弃草稿时，未归档的 AI 输入临时文件应被清理；确认创建时，未选择归档的临时文件按清理策略处理，已选择归档的 PDF 才迁移为正式项目附件。
- 用户访问 AI 建档页时，系统会顺手清理超过保留时间的待确认草稿，并删除对应临时输入文件。

### 4.6 创建正式项目

用户确认后，系统按现有项目新增逻辑创建项目，并继续复用现有校验：

- 项目名称不能为空。
- 年度必须是有效整数。
- 金额必须为空值或有限数字。
- 合同开始日期不能晚于合同结束日期。
- 日期必须是有效 `YYYY-MM-DD`。

创建成功后，系统跳转到项目详情页，让用户继续补充附件和年度执行信息。

如果 AI 草稿包含合同开始和结束日期，确认创建项目后应自动同步年度执行记录。

### 4.7 原始材料处理

AI 输入材料和正式项目附件要区分。

MVP 建议：

- AI 输入文件先保存到临时目录或 AI 草稿目录。
- 用户确认创建项目后，可以保留一条“AI 输入来源记录”，用于追溯识别依据。
- AI 输入图片不自动成为正式项目附件。
- 如果输入文件是 PDF，系统可以让用户选择是否将其作为正式附件上传到项目级附件中。

PDF 输入可选归档类型：

- 采购依据。
- 合同审签 PDF。
- 盖章合同扫描件。
- 其他附件。

默认不自动归档，除非用户明确选择。

### 4.8 AI 调用配置

系统通过外部 AI/API 完成识别。需求层面只定义调用边界，不在文档中保存任何 API key。

初版固定优先使用阿里云百炼 DashScope 兼容 OpenAI 接口，模型建议使用 `qwen3-vl-plus`。选择该模型的原因是它具备文本、图片理解能力，适合合同 PDF 转文本、合同截图和用户说明文字的综合抽取；如果后续实际成本、速度或可用性不合适，可通过环境变量切换为同系列模型。

用户可在系统“设置”页维护 AI 开关、API key、模型、Base URL、代理、超时、上传大小和草稿保留时间。保存后系统写入本项目 `.env` 文件，并同步更新当前运行进程；API key 在设置页明文显示，便于本地核对。

默认配置建议：

- `PROJMAN_AI_ENABLED`：是否启用 AI 模块，默认 `false`。
- `PROJMAN_AI_PROVIDER`：AI 服务提供商，默认 `aliyun_dashscope`。
- `PROJMAN_AI_BASE_URL`：AI API Base URL，默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
- `PROJMAN_AI_MODEL`：用于识别的模型名称，默认 `qwen3-vl-plus`。
- `PROJMAN_AI_API_KEY`：API key，可由环境变量显式提供。
- `PROJMAN_AI_CREDENTIAL_SOURCE`：凭据来源标识，默认 `env_then_optional_file`。
- `PROJMAN_AI_CREDENTIAL_FILE`：可选凭据文件路径，默认空；只有显式配置时才尝试读取。
- `PROJMAN_AI_PROXY`：可选代理地址。
- `PROJMAN_AI_TIMEOUT_SECONDS`：调用超时时间，建议默认 300 秒。
- `PROJMAN_AI_MAX_UPLOAD_MB`：单文件上传大小上限，默认 10。
- `PROJMAN_AI_DRAFT_TTL_HOURS`：待确认草稿保留小时数，默认 24。

凭据读取规则：

- 优先使用环境变量 `PROJMAN_AI_API_KEY`。
- 只有在 AI 功能启用、环境变量未提供 key、且 `PROJMAN_AI_CREDENTIAL_FILE` 显式配置时，才尝试从凭据文件读取。
- 未显式配置凭据文件时，不访问任何固定本机路径。
- AI 功能关闭时不得读取凭据文件。
- 密钥不得写入需求文档、日志、测试快照、普通业务页面或导出文件；设置页作为本地单用户配置页面，可按当前使用偏好明文展示 API key，便于核对和修改。

### 4.9 AI 调用失败处理

AI/API 可能失败，系统必须返回可理解的错误，而不是 500。

常见失败：

- 未配置 API key。
- API 超时。
- 网络或代理不可用。
- 文件过大。
- 模型不支持图片或 PDF。
- AI 返回非 JSON 或字段不完整。

失败时页面应提示：

- 失败原因的中文概括。
- 用户可以重试。
- 用户可以改为手工新建项目。

HTTP 状态策略：

- 用户输入问题，例如空输入、不支持文件类型、文件过大，返回 `400`。
- AI 配置问题，例如已启用但没有可用 API key，返回 `400` 并显示中文配置提示。
- AI 服务超时、网络异常、模型返回非 JSON 等外部服务失败，在 HTML 表单页内返回 `200` 并展示错误提示，不创建草稿；如果后续新增纯 API 接口，再另行定义 `502/503` 契约。

### 4.10 AI 输出校验

AI 返回结果不能直接信任。系统必须在服务端做结构化校验：

- 年度必须能解析为整数。
- 金额必须能解析为有限数字。
- 日期必须能解析为有效日期。
- 合同开始不能晚于合同结束。
- 项目名称去除空格后不能为空。

校验失败的字段可以保留在草稿页，但应标记为“需人工修正”，不能直接确认创建。

AI 原始输出进入草稿前应生成字段级校验结果：

- 可解析且可信的字段标记为“可确认”。
- 空项目名、非法金额、非法日期、开始日期晚于结束日期等字段标记为“需人工修正”。
- 含有“需人工修正”字段的草稿可以展示，但不能直接确认创建；用户修正后才能提交确认。

### 4.11 日志与隐私

AI 模块会处理合同、金额、供应商等敏感信息，应遵守以下要求：

- 不在普通日志中输出完整合同文本、图片内容、API key。
- 不在错误信息中展示密钥。
- 只保存必要的 AI 调用摘要，例如调用时间、输入类型、是否成功、错误类型。
- 用户确认放弃草稿后，未归档的临时文件应清理。
- AI 原始输出如需保存，只能用于排查和草稿复核，不应在普通业务页面、日志或导出文件中完整展示；设置页明文显示 API key 是本地配置入口的明确例外。

## 5. 页面需求

### 5.1 AI 建档输入页

页面元素：

- 文件上传控件。
- 文本输入框。
- 输入材料说明。
- `开始识别` 按钮。
- 识别失败提示区域。

页面提示应明确：

- AI 结果仅供参考。
- 创建项目必须经过人工确认。
- 图片输入仅用于识别，不默认作为正式附件。

### 5.2 AI 识别结果页

页面元素：

- 左侧或上方展示 AI 提取字段。
- 每个字段可编辑。
- 每个字段显示来源摘录和置信度。
- 显示 AI 总结和风险提示。
- 显示原始材料文件名。
- `确认创建项目`、`重新识别`、`放弃草稿` 按钮。

### 5.3 创建成功后的跳转

确认创建后跳转项目详情页，并在页面顶部提示：

```text
已根据 AI 草稿创建项目，请继续核对年度执行和附件归档。
```

## 6. 数据需求

MVP 可新增 AI 草稿数据对象，用于支持“识别后复核再确认”。

AI 草稿建议字段：

- 草稿 ID。
- 用户会话 ID 或创建者标识。
- 输入类型：PDF / 图片 / 文本 / 混合。
- 输入文件名。
- 输入文本摘要。
- AI 原始结构化输出。
- 标准化后的项目草稿字段。
- 字段来源与置信度。
- 状态：识别中 / 待确认 / 已创建 / 已放弃 / 识别失败。
- 关联项目 ID。
- 创建时间。
- 更新时间。

AI 输入文件建议单独存储，例如：

```text
data/ai_inputs/
```

真实数据不进入 Git。

## 7. 非功能需求

- AI 调用应有超时，避免页面长时间卡死。
- 单次上传文件默认限制为 10 MB，超过限制时不调用 AI/API。
- AI 模块关闭时，页面应隐藏入口或提示“AI 功能未启用”，且不得读取本机凭据文件。
- AI 模块的后端逻辑应与现有项目新增逻辑分离，最终确认时再调用现有创建项目服务。
- 所有 AI 识别结果必须经过现有项目校验逻辑。
- 测试中不得真实调用外部 AI/API，应使用 fake client 或 mock 响应；测试也不得读取真实凭据文件。

## 8. 验收标准

### 8.1 文本识别建档

1. 用户进入 AI 建档页。
2. 输入一段包含项目名称、金额、合同期的文字。
3. 系统生成项目草稿。
4. 用户修改草稿字段。
5. 用户确认创建。
6. 系统创建正式项目并跳转详情页。
7. 项目字段以用户确认后的内容为准。

### 8.2 PDF 合同识别建档

1. 用户上传合同 PDF。
2. 系统调用 AI/API 识别合同信息。
3. 草稿页展示项目名称、合同金额、合同期等字段。
4. 草稿页展示字段来源和置信度。
5. 用户确认后创建项目。
6. 如果用户选择归档原 PDF，系统按用户选择的附件类型保存。

### 8.3 图片识别建档

1. 用户上传合同或审批截图。
2. 系统调用支持图像理解的 AI/API。
3. 系统生成草稿并标明来源为图片。
4. 用户确认前可修改字段。
5. 图片不默认成为正式项目附件。

### 8.4 异常处理

- 未配置 AI 时，访问 AI 建档页应有明确提示。
- API 超时时页面显示中文错误。
- AI 返回无法解析的内容时，页面显示“识别失败，可重试或手工新建”。
- AI 识别出的非法金额、非法日期不能直接确认创建。
- 用户放弃草稿后，不创建项目。
- 空输入提交、文件过大、PDF 无可提取文本且无法渲染页面图片时，不调用 AI/API，不创建草稿。
- 已放弃或已创建的草稿不能再次确认。

## 9. 当前不纳入 MVP 的范围

- 批量识别多个项目。
- 自动登录 OA、采购或财务系统抓取材料。
- 自动生成合同审签材料。
- 自动判断采购方式是否合法。
- 自动付款、自动验收。
- 多模型对比评审。
- 对历史附件批量补抽取。
- 将图片直接作为正式附件长期归档。
